A LuCI app for OpenWrt / ImmortalWrt. It uses the connection data of [mihomo](https://github.com/MetaCubeX/mihomo) (Clash Meta, the core behind OpenClash) to break traffic down by device, outbound node and destination domain, with a history view and a real-time speed panel.

On routers with full-cone NAT (`kmod-nft-fullcone`), nlbwmon never receives conntrack events and its statistics stay empty. This app does not rely on conntrack; it reads mihomo's connection table instead, so it can replace nlbwmon for questions like "which device used how much traffic, through which node, to which sites".

## Features

- By device / outbound node / destination: upload and download per device, how much traffic each proxy node (including DIRECT) carried, and the busiest domains. Dimensions can be combined freely, and clicking any of them drills down with a filter.
- History: hourly (within 72 hours) or daily (up to 30 days), grouped by direction, device or outbound node.
- Charts: node share, device → node flow (Sankey diagram) and top destinations, built on a locally bundled Apache ECharts with no external CDN.
- Real-time panel: the browser connects straight to mihomo's WebSocket and refreshes the total speed chart every second, along with per-device speeds and the most active connections.
- Theme support: follows the light and dark modes of Argon, Bootstrap and other themes, including their accent color.
- Lightweight: the collector is written in ucode, with no Python, Node or database. Measured at about 1.3% of one core and about 3 MB of resident memory.
- Command line: `mihomo-traffic stats` prints a report right in SSH.

## Install

Requires OpenWrt or ImmortalWrt 24.10 or later, with OpenClash installed and running (the app reads the mihomo controller port and secret from OpenClash's config).

Download the package from [Releases](https://github.com/hoobnn/luci-app-mihomo-traffic/releases/latest) and copy it to `/tmp` on the router (e.g. `scp -O luci-app-mihomo-traffic*.apk root@192.168.1.1:/tmp/`). The package is architecture-independent and works on x86_64, aarch64, mips and others.

### 25.12 and later (apk)

```sh
apk add --allow-untrusted /tmp/luci-app-mihomo-traffic-*.apk
```

### 24.10 (opkg)

```sh
opkg install /tmp/luci-app-mihomo-traffic_*.ipk
```

The collector starts automatically after install. Refresh LuCI and the page appears under Status › Mihomo 流量. Data is collected from the moment of install.

### Update

Download the new package and install it with the same command to upgrade in place. The collector restarts on its own after install, and history is kept.

### Uninstall

`apk del luci-app-mihomo-traffic` or `opkg remove luci-app-mihomo-traffic`. History stays in `/etc/mihomo-traffic/`; delete it by hand if you no longer need it.

## Usage

### Web UI

- History: pick a time range, a trend grouping and table dimensions. Clicking a device, node or destination in a chart or table adds a filter; click the filter tag to remove it.
- Real-time: connects to mihomo's WebSocket only while this tab is open, and disconnects when you leave. The browser must be able to reach the router's mihomo controller port directly (9090 by default in OpenClash). When LuCI is opened over HTTPS, the browser blocks `ws://` connections and the real-time panel is unavailable.

### Command line

```sh
mihomo-traffic stats                 # last 24 hours, by device
mihomo-traffic stats 2 src,host      # last 2 hours, by device and destination
mihomo-traffic stats 168 node        # last 7 days, by outbound node
```

Dimensions are `src`, `node`, `host` and any combination of them. The `(内部)` (internal) row is connections opened by mihomo itself (carrier connections of chained proxies, DoH and so on). It overlaps with device traffic and is left out of the totals.

## How it works

```text
mihomo /connections ──polled every second──▶ mihomo-traffic (ucode process under procd)
                                              │ accumulates byte deltas per device / node / destination
                                              ├─ snapshot every minute ─▶ /tmp/mihomo-traffic.cur
                                              └─ archive every hour ────▶ /etc/mihomo-traffic/YYYY-MM-DD.tsv
                                                                            │
LuCI page ◀── rpcd (ucode plugin luci.mihomo-traffic) ──────────────────────┘  query, cache, daily rollups
     └──── real-time panel talks to mihomo's WebSocket directly (/traffic, /connections, /memory)
```

- Storage: one row per device + node + destination per hour; destinations under 16 KB in an hour are merged into `(小流量)` (small traffic). Data is kept for 30 days and preserved across sysupgrade.
- Queries: within 72 hours, hourly raw data is read; longer ranges read daily rollups (destinations under 1 MB a day are merged into `(小流量)`). A 30-day query takes about 0.5 seconds, and unchanged data is served from cache.
- Accuracy: mihomo's API exposes connection snapshots, not events, so connections that live less than a second, and the last second or so of traffic before a connection closes, are missed. DIRECT traffic is only counted when it passes through mihomo (e.g. in TUN or transparent proxy mode).

## FAQ

**Why doesn't nlbwmon work with full-cone NAT?**
`kmod-nft-fullcone` takes over conntrack event notifications, so nlbwmon receives no connection events and its statistics stay empty. This app reads mihomo's connection table and is not affected.

**Why don't the numbers match my ISP or VPS dashboard?**
This app counts the bytes of connections that pass through mihomo. Protocol overhead, retransmissions and traffic that bypasses mihomo are not included, and carrier connections of chained proxies are shown separately as `(内部)`.

**Does it slow down my network?**
No. The collector only reads mihomo's API, is not in the forwarding path, and runs at the lowest priority (nice 19).

## Build from source

The app is laid out as a standard OpenWrt LuCI package and can be built from a feed in any OpenWrt SDK:

```sh
# in the OpenWrt SDK directory
echo "src-link mihomo /path/to/feed" >> feeds.conf.default   # put this repo in the feed directory, named luci-app-mihomo-traffic
./scripts/feeds update -a && ./scripts/feeds install luci-app-mihomo-traffic
make package/luci-app-mihomo-traffic/compile
```

CI uses [openwrt/gh-action-sdk](https://github.com/openwrt/gh-action-sdk) to build with the 25.12 (apk) and 24.10 (ipk) SDKs, and publishes a release when a `v*` tag is pushed.

### Development

```sh
scripts/deploy.sh root@192.168.1.1   # copy files to the router and reload rpcd; restarts the collector only if its logic changed
sh tests/smoke.sh                    # run smoke tests on a router or in an OpenWrt rootfs container
scripts/build-echarts.sh             # rebuild the trimmed ECharts bundle (needs Node.js)
```

Demo environment (for screenshots; do not run it on a real router, it overwrites existing data):

```sh
ucode -L /usr/share/ucode tests/demo-data.uc               # generate 8 days of fake data on a test router or container
uv run --with websockets tests/fake-mihomo.py 19090       # fake mihomo WebSocket that feeds the real-time panel
```
